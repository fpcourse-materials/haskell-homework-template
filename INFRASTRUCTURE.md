# Общая инфраструктура домашних заданий

Шаблон — единственный источник служебной инфраструктуры. В каждой домашке изменяются только точные пути из [HOMEWORK_FILES](HOMEWORK_FILES): условия, примеры, тесты задач и конфигурация состава модулей, вида домашки, линтера и интерпретатора. Новый файл задания сначала добавляется в этот список в общем шаблоне. Makefile, workflow, проверялки, библиотеки, общие тестовые модули и инструменты изменяются в шаблоне, после чего обновляются в домашках.

Преподавательские цели и их описания находятся внизу Makefile. Обычный `make` показывает только студенческие команды. `make check-report` читает номера задач из TASKS и проверяет JSON-отчёт заготовки; отдельный скрипт с зашитыми номерами для каждой домашки не нужен.

В `fp2026/hws` команда `make new HW=NN` создаёт домашку непосредственно из общего шаблона. `make template-check HW=NN` сверяет все общие файлы побайтово, включая новые или отсутствующие файлы. `make template-sync HW=NN` обновляет их из шаблона, сохраняя файлы заданий и конфигурации, git-историю и результаты сборки. Неизвестный файл вне списка разрешённых отличий блокирует обновление: сначала нужно перенести его в общий шаблон или зарегистрировать как файл задания. Проверки `smoke` и `reference` начинаются с проверки инфраструктуры.

Из каталога шаблона те же операции доступны как `make infrastructure-check HOMEWORK=/путь/к/домашке` и `make infrastructure-sync HOMEWORK=/путь/к/домашке`. `make tools-test` проверяет служебные инструменты без сети; `make checker-check` проверяет λ-проверялку. После изменения общей инфраструктуры запускаются эти проверки и проверки затронутых домашок.

`make publish-template MSG="Описание изменений"` проверяет инструменты и строгую сборку, коммитит изменения общего шаблона и отправляет main в `fpcourse-materials/haskell-homework-template`. Общий шаблон публичный и содержит только обвязку; репозитории домашних заданий с эталонами остаются приватными. Шаблон публикуется до создания репозиториев домашних заданий, чтобы их общие файлы наследовались из уже сохранённой истории.

Локальное обновление файлов не публикует шаблон и домашки. Для публикации служит общая цель `make release PUBLIC_REPO=организация/имя`: условия остаются в main, эталон — в solutions приватного origin, публичный студенческий шаблон получает только main. Общие файлы, тесты и конфигурация ветки solutions обновляются из main через `make solutions-sync`; эта цель сохраняет файлы решений `src/Level1.hs`, `src/Level2.hs`, `src/Level3.hs` и `src/hw.lam`. Дедлайн для этой процедуры не требуется.
