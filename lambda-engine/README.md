# Как писать λ-домашки

Задания лежат в `src/hw.lam`, определения с лекции и практики — в `src/prelude.lam`. На месте каждой дырки `...` пишется ответ, условие — в комментарии перед задачей. Проверка — `make check`, как и в остальных домашках.

## Термы

```
name = \x y. body        -- определение; \x y. — то же, что \x. \y.; можно писать λ или ->
f x y                    -- аппликация, скобки только для группировки: f x y это (f x) y
3                        -- число Чёрча ⌜3⌝ = \s z. s (s (s z))
...                      -- дырка: сюда пишется ответ
-- текст                 -- комментарий
```

Имена — буквы, цифры, `_` и штрих: `K'` в прелюдии — это K* с лекции. Свободные переменные можно использовать только те, что перечислены в строке `vars` в начале файла; любое другое незнакомое имя проверялка считает опечаткой.

## Интерпретатор

`cabal run lambda -- load src/hw.lam` загружает файл вместе с прелюдией и открывает интерпретатор. Терм сам по себе редуцируется до нормальной формы (`mult 2 3`):

* `:follow терм` показывает каждый шаг, `:step` — один шаг;
* `:explain терм` рисует дерево терма;
* `:decode терм` печатает результат как число, пару или список;
* `:type терм` выводит наиболее общий тип;
* `:r` перечитывает файл после правок, не выходя из интерпретатора;
* `:help` — всё остальное.

Отчёт по всему файлу без тестового раннера: `cabal run lambda -- check src/hw.lam`.

## Проверки

Проверки в файле — открытые тесты, их можно и нужно читать:

* `expect левое = правое` вычисляет обе стороны и сравнивает их с точностью до α и η;
* `chain name = ...` — цепочка редукций по шагу на строку: `~b~>` один β-шаг, `~d~>` раскрыто или свёрнуто одно имя, `=a=` переименование связанной переменной, `~s~>` выполнена подстановка, `~~>` до трёх шагов сразу. Если проверялка не согласна с переходом, она скажет, между какими строками и какие шаги были возможны;
* `free`, `rename`, `minimal`, `check`, `type`, `church`, `inhabit`, `family` объяснены в условиях тех задач, где встречаются.

Задача считается TODO, пока все её проверки упираются в дырку; PARTIAL — когда часть проверок прошла; DONE — когда все. Полное описание формата — в [FORMAT.md](FORMAT.md).
